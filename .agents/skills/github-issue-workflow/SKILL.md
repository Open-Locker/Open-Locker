# GitHub issue workflow

Draft the issue in chat first, search for duplicates, and update an existing
issue when it already covers the work. Use component labels (`backend`,
`mobile-app`, `iot client`, `docs`) and split independently deliverable,
multi-track work into sub-issues. Keep decisions auditable by linking ADRs and
recording unresolved questions. Keep issue language English and minimize churn.
